LeagueForge VM 1.3.1 — Autosave Hotfix Validation

ROOT CAUSE FOUND
VM 1.3 did call autosave frequently, but persistence had two race/lifecycle defects:

1. IndexedDB writes were asynchronous and not serialized.
   An older captured state could finish writing after a newer one.
   The IndexedDB record timestamp was assigned when the async write finished,
   so that stale state could also look "newer".

2. Automatic resume only considered IndexedDB records.
   A more recent localStorage fallback could exist and still be ignored.

On iOS/PWA there is an additional lifecycle risk: pagehide/visibilitychange do not guarantee
that a pending IndexedDB Promise will be allowed to finish before the app is suspended.

HOTFIX DESIGN
- Every autosave writes a compact synchronous emergency copy to localStorage first.
- IndexedDB autosaves are serialized through one Promise queue.
- IndexedDB savedAt uses payload.savedAt (capture time), never async completion time.
- A stale payload is refused if IndexedDB already holds a newer payload.
- Resume compares payload.savedAt across:
  * IndexedDB autosave
  * IndexedDB checkpoints
  * IndexedDB manual save
  * emergency local copy
  * normal local autosave
  * manual local copy
  * legacy copies
- Boot resumes the newest state before compaction/migration.
- visibilitychange/pagehide use the new sync-first autosave automatically.
- beforeunload adds another safeguard.
- 30-second foreground watchdog writes an emergency checkpoint.
- Save schema/client: 5.3.1 / VM1.3.1.
- Existing VM 1.3 saves remain compatible.

VALIDATION
- JavaScript syntax: PASS
- Service Worker syntax: PASS
- Manifest parse: PASS
- Focused autosave ordering/recovery logic: 5/5 PASS
  1. payload timestamp beats async completion timestamp
  2. queued writes preserve newest state
  3. stale-write guard rejects older payload
  4. newer emergency copy beats older IndexedDB
  5. newer snapshot can recover over stale autosave
- Existing VM 1.3 game/balance code is unchanged apart from save persistence.
- VM 1.3 previously passed 84/84 game/balance tests; this hotfix adds 6 in-app autosave diagnostics.

RECOVERY NOTE
There is a real chance VM 1.3.1 can recover a season that VM 1.3 failed to resume if the
correct state still exists in an IndexedDB snapshot/checkpoint or local fallback.
It cannot reconstruct a state that was never persisted anywhere.
